# Hyokeisan integer grid: selfhost Wasm experiment, 2026-11-02

`src/hyokeisan/grid.kotoba` is a small pure 4×4 integer grid kernel. It is not
a workbook, formula engine, editor, persistence implementation, or release
artifact. It preserves the input vector on rejected writes and uses persistent
updates for valid writes. Invalid reads require a separate validity check.

The source SHA-256 was
`0b5ee95de3b9f9e8d023e5d91c8b66e1b66cf4616589b74faac560ff7dea8361`.
The native Amu CLI returned 0. Amu commit
`d4d6841f129d846db13393a469645e1ca91fb568` macOS ARM64 full-root, SHA-256
`f5d36c21efff28c8fdc1125832c99607ee0f09d0ec1db1290213d72f77d43b5b`,
compiled the kernel to wasm32-browser. Chrome 156.0.8078.74 ran the result in
Amu's Worker harness with no granted wires and returned `:status :ok :result 0`.
Wasm SHA-256: `e1e08143b8827c73632f0cdaf0c3210fadfb5bb5397086740e4755359d837fdf`.
Changing the row stride from 4 to 3 returned `:result 1` in the same harness.
No user data or external operations were used.

Reproduce on macOS ARM64 with the pinned Amu checkout:

```sh
python3 scripts/check-grid-wasm.py /path/to/amu /new/output/directory /path/to/Chrome
```

The check does not qualify UI, persistence, migration, arithmetic overflow
behavior, external formats, network integration, or publication.
